## Принятые решения

1. Equity — фиксированная позиция №1.
2. Изменённый Lot variant redundancy — №2; окончательные fallback cases открыты.
3. Согласованный A/B — №3.
4. Зависимость от топ-5 — №4, включена в целевой конфигурации, доля **>80%**.
   История >=45 суток, >=25 прибыльных завершённых циклов, без вычитания
   комиссий. Ниже границ — диагностика без исключения. Ровно 80% проходит.

Time consistency убрать из панели/отбора; расчёты периодов и Excel сохраняются.
Обработка NO_TRADES должна быть исправлена по рабочему плану.
Эти решения ещё не внедрены в runtime. Остальные предложения ниже не приняты.

### Проверка Low trades на базе

- Scope pair_side: 61 группа; в 30 нижняя граница <=0; всего 51 исключение.
- Scope pair_side_timeframe: 357 групп; в 81 нижняя граница <=0;
  всего 583 исключения.
- При неположительной границе ни одна неотрицательная частота не исключается.
- Большее число сделок не означает больший PnL или меньший DD. Например,
  высокая частота сама по себе не исправляет слабую среднюю сделку.
- Группа меняется после каждого предыдущего фильтра; данные цифры нельзя
  перенести на конечный pipeline без его отдельного воспроизведения.

## 2. Все Pareto-варианты

Обычное Pareto исключает строку, когда другая не хуже по всем указанным
координатам и строго лучше хотя бы по одной. Допуска улучшения нет.
Равные строки остаются. Неполные координаты не участвуют в доминировании.
Большинство стадий не проверяют равенство периодов и режима sizing;
scope pair_side_timeframe задаёт только TF внутри выбранной пары/стороны.

Здесь `R=min(A/30,B/30)`, `D=max(full DD,B DD)`, `H=max(full Hold p95,B Hold p95)`.
DD5 — `full PnL/30 * 5 / full DD`, расчётный proxy. Capital —
`sum(lot_x)*5/full DD+0.05`, а efficiency — DD5 / capital.

| Stage / UI-вариант | Координаты / особое правило | Рекомендация |
| --- | --- | --- |
| `pareto_window_b` | B PnL и B Trades/30 ↑; B DD и B Hold p95 ↓ | Частота сделок получает самостоятельный бонус без подтверждённой пользы; исторический A не защищён. Не включать автоматически. |
| `pareto_window_b_dd_shift` | B PnL и Shift1 ↑; full DD ↓ | Практичнее Window B, но интересует только B. Оставить альтернативой. |
| `pareto_dd5_balanced` | DD5 и Shift1 ↑; capital, full Hold p95 и Close MA ↓ | Пять координат смешивают результат, proxy и предпочтения настроек. Может сохранить слабого уникального лидера по Shift. Не использовать как единственное качество. |
| `pareto_robust` | R и Shift1 ↑; D и H ↓ | Наиболее полезный существующий общий вариант после hard filters. Min(A,B) может скрыть ухудшение одного из периодов; Shift защищает необычные настройки. |
| `pareto_plateau_points_per_order` | Только одинаковый ORD: DD5 другой >=2*DD5 кандидата и каждый plateau count не меньше | Plateau — source support, не готовый trading outcome. Нужны исправление неположительного DD5 и проверка отсутствия ухудшения B/DD. Пока оставить OFF. |
| `pareto_plateau_points_total` | То же, но сравнивается сумма plateau counts | Большая сумма может скрыть один слабый ордер. Per-order информативнее для такого допуска. |
| `pareto_efficiency_shift` | Efficiency и Shift1 ↑ | Ни B, ни raw DD напрямую не защищены; похож на выбор по proxy. Не добавлять к общему каскаду по умолчанию. |
| `pareto_dd5_holding` | DD5 ↑, full Hold p95 ↓ | Полезен для сравнения скорости оборота, но может исключить лучший B. Альтернатива, не обязательный дополнительный слой. |
| `pareto_dd5_close_ma` | DD5 ↑, Close MA ↓ | Предпочтение настройки закрытия без защиты B/DD. Опция. |
| `pareto_dd5_first_shift` | DD5 и Shift1 ↑ | Аналогичное структурное предпочтение без защиты B/DD. Опция. |
| `pareto_conditional_close_ma` | Только >3 survivors: efficiency ↑, Close MA ↓ | Число соседей не меняет торговое качество. Условие >3 не является statistical gate. Опция. |
| `pareto_primary` | DD5 ↑, capital ↓ | Точная копия следующего алгоритма при одинаковом scope и входной группе. Оставить один понятный вариант. |
| `pareto_dd5_capital` | DD5 ↑, capital ↓ | Дубликат Primary; повторное применение подряд к его survivors не даёт нового Pareto-отсева. |
| `pareto_shift_near_tie` | R допускает падение до 10%; Shift1 выше >=10bp; D/H не хуже; оба R>0 | Сужает близкие варианты, но разрешает пожертвовать PnL ради Shift. Добавить защиту обычного B; проверить 0% tolerance bug. |
| `pareto_close_ma_near_tie` | R допускает падение до 10%; Close MA строго меньше; D/H не хуже | Аналогичное предпочтение меньшего Close MA, default OFF. Включать только при принятом бизнес-предпочтении. |

### Почему набор простых Pareto не равен одному общему

Стратегия с лучшим B может проиграть отдельному DD5/Close MA фильтру, который
B вообще не сравнивает. Отключённый или отсутствующий критерий не защищает
стратегию. Увеличение числа координат в одном Pareto обычно затрудняет
доминирование; последовательность разных небольших Pareto может вырезать
важные альтернативы. Для сужения выборки полезнее одно согласованное
сравнение результатов после минимальных требований качества.

## 3. Два final ranking и встроенное сокращение аналогов

Одна fixed final stage `rank_robust_top_n`, current default N=20, scope pair_side.
Остальные проверенные этапы — 23 movable stages: всего 24 stage IDs.

| Метод | Как выбирает | Ограничение |
| --- | --- | --- |
| `robust_v1` | Percentiles: robust PnL 30%, worst DD 15%, A/B stability 15%, worst Hold 12%, Shift1 10%, min plateau points 9%, Close MA 9%. Missing weights renormalize. | Относительный лидер группы может быть абсолютно слабым. Holding сравнивается между TF в score. Неполнота может повысить score за счёт удаления слабого компонента. |
| `equity_quality_v1` | Сначала GROWING/WEAKENING и остальные classes, затем score=G*Q*(1-D)*(1-P) для роста на доступном H. Tie-break D, P, H, ID. | Полезен для выбора ровной текущей кривой, но PnL всей истории и абсолютный риск не являются hard gates. GROWING сортируется выше WEAKENING даже при меньшем score. |

Top-N ограничивает размер выхода. Оно не доказывает, что строка за N — мусор.
Unrankable строки попадают в RESERVE; missing data нельзя называть проигрышем.
До Top-N текущий runtime сворачивает структурные analog groups по одинаковым
plateau keys, TF/ORD и нетранзитивным соседним CMA-блокам; выбирает лучшего
по выбранному ranking с учётом prior rejection. Это уже помогает сокращать
похожие варианты, отдельный второй identical mechanism не нужен.

## 4. Подтверждённые ошибки и незакрытые вопросы порядка

1. **0% tolerance становится 10%.** `_near_tie_eliminated` использует
   `(stage.pnl_tolerance_pct or Decimal(10))`. Parser разрешает ноль.
   Synthetic check: PnL=10, Shift=100 против PnL=9.5, Shift=110, одинаковые
   D/H; при submitted tolerance=0 первая строка ошибочно исключена.
2. **Plateau на неположительном DD5.** Две строки DD5=-1, counts=10,
   multiplier=2 исключают друг друга: `-1 >= -2` верно для обеих.
   Нужен контракт для неположительных baselines; не применять multiplier
   как доказательство роста к отрицательной базе. Runtime сейчас не исправлялся.
3. **Доходность и DD зависят от периода.** В большинстве Pareto нет равенства
   окон. Старая хорошая история и свежая плохая могут сравниваться как один
   cohort; нормирование /30 само по себе не делает рыночные периоды одинаковыми.
4. **Замена lot representative до A/B/топ-5.** Представитель может позднее
   провалить правило, а ранее удалённая альтернативная lot-версия — пройти.
   Вопрос уже открыт в плане для A/B, теперь включает топ-5. Нужно определить
   eligibility-aware выбор представителя или fallback по полной исходной группе;
   user-approved порядок №1–4 не менять скрытым переставлением стадий.
5. **Утрата оценки vs плохой результат.** NOT_EVALUATED, missing cache,
   мало истории и NO_TRADES имеют разные причины. Ни одно нельзя превращать
   в доказанный плохой PnL. Предлагаемый резерв для недостаточных доказательств
   требует отдельного контракта и не меняет текущие правила автоматически.

Оба code findings воспроизведены прямым вызовом production helpers с assert.
Новые unit tests/runtime fixes и independent code review пока не выполнялись.

## 5. Новые конструкции — предложения, не утверждённые пороги

### Приоритет 1: доходность относительно принятого риска

Текущая система не задаёт hard минимум результата относительно полного DD.
DD5 Pareto сравнивает только соседей; даже лучший из слабой группы проходит.

Кандидат для исследования:

```text
P = full_pnl30 / full_dd_pct
PB = B_pnl30 / full_dd_pct
exclude if P < r AND PB < r
```

То есть слабые full и B одновременно относительно исторического риска.
Использовать только валидный DD>0, известные full/B returns, >=45 суток и
>=25 завершённых сделок (здесь всех, не только прибыльных). DD=0, unknown
и отрицательные/невалидные метрики не получают искусственный finite ratio.
Исследовать r=0.3/0.5/0.75; ни один пока не выбран.
При r=0.5 полный DD=20% требует full или B/30 не ниже 10%.
Это screening proxy, не гарантия окупаемости DD и не реальный DD5 retest.

Отдельный hard ceiling `full DD > Dmax` полезен, если оператор задаёт
максимально приемлемый риск. Dmax — требование пользователя, а не статистический
квартиль. Можно исследовать уровни 15/20/25%, не выдавая один из них за оптимум.

### Приоритет 2: долгое удержание при слабой отдаче

Доработать существующий Holding, а не добавлять второй похожий checkbox:

```text
long_hold = holding_p95 > Q3 + 1.5*IQR in comparable TF cohort
exclude if long_hold AND P < r AND PB < r
```

Минимум завершённых позиций для p95, guards достаточности группы и
устойчивость threshold при множестве схожих вариантов требуют проверки.
Стартовая гипотеза для исследования: >=25 completed cycles, cohort>=20.
Длинное прибыльное удержание остаётся. При таком определении стадия вложена
в hard risk-return floor с тем же r: если floor включён, Holding не даёт
дополнительных исключений. Это **альтернативный более осторожный** вариант
применения ratio, либо будущий иной согласованный r; не обещать эффект от обоих.

### Приоритет 3: зависимость от одного рыночного эпизода

Топ-5 пропускает историю, где 10–20 хороших сделок собрались в одном движении.
Предлагается концентрация signed completed-cycle PnL по датам закрытия:

```text
week_peak = maximum PnL of completed cycles closed inside any rolling 7d interval
remaining = total_completed_pnl - week_peak
```

Для первого исследования: история >=90 суток, >=50 завершённых циклов,
>=6 недель с завершёнными сделками. Недель без сделок не считать убыточными.
Самый осторожный кандидат исключения — remaining<=0; долю >80% сначала
показывать диагностикой. Rolling 7d избегает зависимости от границы календарной
недели. Без пересчёта sizing это арифметическая диагностика, не альтернативный
backtest. Burst of legitimate profits может быть особенностью стратегии;
требуется показать конкретные дополнительные исключения после согласованного топ-5.

### Приоритет 4: замена множества Pareto одним сравнением A/B/DD

Исследовать performance Pareto с A/30↑, B/30↑, full DD↓ в одинаковых
периодах и сопоставимом sizing, default scope pair_side_timeframe.
Так улучшение DD5 или min(A,B) само по себе не скроет ухудшение B/A.
Shift/Close MA — последующие принятые предпочтения, а не обязательные
доказательства прибыльности. Для meaningful dominance исследовать margin,
например >=10% улучшения PnL одного положительного периода либо >=10%
уменьшения DD при остальных координатах не хуже. Отрицательная база требует
абсолютного сравнения, не относительного multiplier.
Margin сохранит больше близких вариантов, чем обычное strict Pareto;
не обещать, что сам по себе он сильнее сузит выборку.

### Приоритет 5: резерв при недостаточной доказательности

Диагностика истории, actual completed cycles, completeness и cache validity
должна отделять слабую стратегию от непроверенной. Кандидаты исследования:
история<30/45 суток или <15/25 completed cycles -> RESERVE/provisional, без
метки проигравшего. Это отдельное соглашение об admission в shortlist;
оно не выводится автоматически из guards топ-5 и не является принятым фильтром.
Прибыльность на короткой истории сохраняется в отчёте.

### Последующие варианты, если первые недостаточны

- Длительное невосстановление **полного исторического** peak: current
  drawdown от полного peak вместе с давностью восстановления. Нужны high
  gap и длительность одновременно; текущий Equity H=28 не охватывает старый
  peak. Конкретные thresholds сначала исследовать, без самостоятельного
  запрета quiet windows или WEAKENING.
- Fingerprint одинаковых completed position schedules в одинаковом интервале:
  находит дубликаты поведения, которые не совпали по settings/plateau keys.
  Hash-grouping дешевле all-pairs correlation. Это redundancy, не оценка мусора;
  выбрать представителя по принятым требованиям качества, сохранить аналоги.
- PF/mean trade PnL: full PF<=1 сигнализирует отсутствие исторической отдачи
  по raw realised PnL, но может описывать старый убыток с восстановлением в B.
  B PF floor частично дублирует B return floor. Не вводить произвольный PF=1.3
  или Win Rate всего периода как новое доказанное hard правило.
- Bootstrap/нижняя confidence bound: отложить. На редких крупных прибылях,
  зависимых циклах и short history простая IID перестановка не подтверждает
  пригодность; новый сложный score без отдельной проверки не нужен.

## 6. Предлагаемая конструкция pipeline

Принятые №1–4 сохраняются. После них исследовать **один** вариант risk-return
допуска (hard floor либо условие вместе с long holding), затем при необходимости
weekly concentration. Выбрать один основной quality Pareto, предпочтения
Shift/Close MA включать отдельно. Заканчивать существующими analog collapse
и Top-N с одним выбранным методом. Номера начиная с №5 ещё не приняты.

Перед внедрением каждого нового правила: отдельные дополнительные исключения
после предыдущих правил, топ-10 по сохранённому PnL, несколько худших случаев,
число provisional/unknown, чувствительность threshold и распределение
инструментов/семейств. Не считать схожие lot/CMA варианты независимыми примерами.
Не добавлять фильтр, который только повторяет отсев предыдущего.

При утверждённых 80% ранее исследованная часть после Equity/current Lot/new A/B
теряет 30 из 70 кандидатов с долей >70%. Это локальное evidence для текущего
Lot; изменённая согласованная lot policy целиком ещё не симулировалась.

## Следующий исследовательский шаг

Приоритет — риск/доходность и его вариант вместе с Holding. Показать реальные
новые исключения после четырёх первых стадий; до полного моделирования нужно
закрыть fallback cases Lot и проблему исчезновения альтернатив после A/B/топ-5.
Все предложения остаются обсуждением, без runtime changes, tester run,
production writes или автоматического признания будущей прибыли.
