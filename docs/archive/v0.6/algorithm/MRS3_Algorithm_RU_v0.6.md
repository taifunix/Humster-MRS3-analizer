# MRS3 — итоговый алгоритм отбора и подготовки стратегий
## Версия v0.6 — базовая версия после разбора алгоритма
Дата: 2026-08-08

## 1. Цель

Этот документ описывает полный процесс, который превращает результаты массового MRS2-тестирования в:

1. библиотеку устойчивых зон входа (`Plateau Library`);
2. одну базовую одноордерную стратегию для пары;
3. естественные многоордерные MRS3-конструкции на 2, 3 и 4 ордера;
4. два варианта распределения лотов для каждой MRS3;
5. готовые JSON для tick-теста;
6. полный Excel-аудит;
7. правила сравнения стратегий после фактического MRS3-тестирования.

Главный принцип алгоритма: **не искать одну красивую точку параметров, а искать устойчивые зоны входа и запоминать, на каких Close MA каждая такая зона сохраняет силу.**

---

# 2. Что такое MRS / MRS3

MRS — mean-reversion стратегия. Лимитный ордер входа находится на заданном процентном отклонении от своей открывающей MA. После открытия позиция закрывается лимитным ордером по закрывающей MA.

MRS3 отличается тем, что одна позиция может набираться несколькими лимитными ордерами. Каждый вход имеет:

- собственный период Open MA;
- собственный entry shift;
- собственный `lot_x`.

Но у всей позиции одна общая Close MA.

Поэтому задача построения MRS3 — не просто найти несколько прибыльных MRS2-точек. Нужно найти **несколько независимых устойчивых зон входа, которые способны работать с одной общей Close MA**.

---

# 3. Входные данные

Минимальный набор:

1. CSV с результатами MRS2-перебора;
2. дата листинга каждой пары;
3. JSON-шаблон MRS3;
4. сторона: LONG или SHORT;
5. фактический период отчета.

Ожидаемые параметры MRS2:

- Pair / Symbol;
- TimeFrame;
- Open MA period;
- Close MA period;
- entry multiplier или непосредственно shift;
- TotalPnLPercent;
- MaxDrawdownPercent;
- WinRate;
- ProfitFactor;
- TotalTrades.

Поддерживаемые TF:

`5m, 15m, 30m, 45m, 1h, 2h, 3h, 4h`

30m должен обрабатываться полноценно, даже если его не было в первых тестах.

---

# 4. Эффективная история

Тестер мог быть запущен раньше листинга инструмента. Поэтому номинальный период отчета не равен фактической истории.

Для каждой пары:

`EffectiveStart = max(ReportStart, ListingDate)`

`D_eff = ReportEnd - EffectiveStart`, в сутках.

Для основного отбора:

`D_eff >= 7 дней`

Если меньше:

`OBSERVE_ONLY_HISTORY`

Такой набор можно хранить, но он не должен давать основной standalone-кандидат.

---

# 5. Базовые метрики

Для каждой валидной MRS2-точки:

`Efficiency = PnL / DD`

Диагностически:

`PnL_DD5_theoretical = PnL * 5 / DD`

Последняя величина показывает, какой PnL соответствовал бы 5% DD при линейном масштабировании риска.

Если `DD <= 0`, нормализация к DD5 не определяется; такая строка должна получить отдельный диагностический статус и не использоваться для DD5-ranking.

---

# 6. Экономические hard gates

Точка проходит экономический фильтр только если одновременно:

- `PnL > 0`;
- `DD > 0`;
- `WinRate >= 70%`;
- `DD <= 11%`;
- `PnL / DD >= 3`.

Эти пороги используются как admission gates, а не как итоговый рейтинг.

PnL/DD нельзя использовать как прямой глобальный рейтинг пар с разной длительностью истории.

---

# 7. Sample filter

## 7.1. Абсолютный floor

Для standalone-кандидата:

- `shift <= 2.0%` → минимум **10 сделок**;
- `shift > 2.0%` → минимум **5 сделок**.

Для дополнительных глубоких MRS3-ордеров этот floor **не является hard reject**.

---

## 7.2. Относительный минимум сделок

Для standalone-кандидата:

`MinTradesRelative = ceil(D_eff * BaseRate_TF * ShiftFactor)`

`MinTrades = max(AbsoluteFloor, MinTradesRelative)`

### BaseRate_TF

| TF | trades/day |
|---|---:|
| 5m | 2.27 |
| 15m | 1.82 |
| 30m | 1.59 |
| 45m | 1.36 |
| 1h | 1.36 |
| 2h | 1.14 |
| 3h | 0.91 |
| 4h | 0.91 |

30m = временная интерполяция между 15m и 45m; значение подлежит перекалибровке.

### ShiftFactor

Текущая рабочая кусочно-заданная шкала:

| Shift | Factor |
|---|---:|
| 0.3–1.5% | 1.00 |
| >1.5–2.0% | 0.90 |
| >2.0–3.1% | 0.30 |
| >3.1–4.7% | 0.20 |

Для `shift > 4.7%` относительный factor пока не калиброван. До накопления данных такие точки могут быть `depth_eligible`, но не получают полноценный `standalone_eligible` только на основании придуманного relative-rate.

---

## 7.3. Два уровня пригодности

Для каждой MRS2-точки храним два признака.

### `standalone_eligible = TRUE`

Точка:

- прошла economic gates;
- прошла `D_eff >= 7`;
- прошла абсолютный и относительный sample filter;
- входит в подтвержденное READY-плато.

Такая точка может быть:

- standalone 1ORD;
- самым мелким ордером MRS3.

### `depth_eligible = TRUE`

Точка:

- прошла economic gates;
- входит в подтвержденное плато;
- но может не пройти жесткий standalone sample filter.

Она может использоваться как 2-й, 3-й или 4-й ордер MRS3.

Это позволяет не уничтожать редкие глубокие entry-зоны только из-за малого количества standalone-срабатываний.

---

# 8. Геометрия поиска плато

Плато ищется в трех измерениях:

`Shift × OpenMA × CloseMA`

Open MA и Close MA сравниваются с соседними периодами `±1`, с учетом фактических границ исследованной MA-сетки.

## 8.1. Fine-zone: shift < 1.5%

Для оценки кандидата нужны доступные shift-соседи с шагом 0.1 п.п. в радиусе до `±0.3 п.п.`.

Пример для shift 1.0:

`0.7, 0.8, 0.9, 1.0, 1.1, 1.2, 1.3`

Если требуемых 0.1-тестов нет, кандидат получает:

`SHIFT_REFINE_REQUIRED`

и формируется точное задание на дополнительные прогоны.

---

## 8.2. Пограничная зона 1.5–1.7%

Проверка асимметрична:

- вниз — максимум `0.3 п.п.`;
- вверх — максимум `0.5 п.п.`.

Например для 1.5:

- вниз: 1.4 / 1.3 / 1.2 при fine-grid;
- вверх: все доступные соседи до 2.0 включительно.

1.0 не считается нижним соседом для 1.5 только потому, что расстояние равно 0.5.

---

## 8.3. Coarse-zone: shift > 1.7%

Берутся **все реально протестированные shift-соседи в пределах ±0.5 п.п.**

Примеры:

- сетка 0.2 → до двух соседей на сторону;
- сетка 0.3 → по одному;
- сетка 0.4 → по одному;
- сетка 0.5 → по одному.

Если в требуемом направлении внутри исследуемого диапазона нет теста на расстоянии не больше 0.5, кандидат получает `SHIFT_REFINE_REQUIRED`.

---

## 8.4. Нижняя граница 0.3%

Shift 0.3 рассматривается односторонне — только вверх.

Значения ниже 0.3 специально не требуются.

Кроме того, shift 0.3 допускается в основной работе только если закрывающая MA имеет ненулевой выгодный сдвиг:

- LONG: текущий close multiplier `1.003`;
- SHORT: текущий baseline `0.997`.

Экономическая целесообразность 0.3 остается параметром для будущей проверки.

---

# 9. Формирование плато без единого PlateauScore

Единый искусственный `PlateauScore` не используется.

Плато определяется через:

1. локальную геометрическую близость;
2. CORE-сходство соседних точек;
3. общий предел деградации всей области.

---

## 9.1. CORE-связь

Для двух геометрически соседних точек A и B:

`PnLRetention_AB = min(PnL_A, PnL_B) / max(PnL_A, PnL_B)`

`EffRetention_AB = min(Eff_A, Eff_B) / max(Eff_A, Eff_B)`

`CoreLink = min(PnLRetention_AB, EffRetention_AB)`

CORE-связь существует если:

`CoreLink >= 0.90`

---

## 9.2. Общая граница плато

Для набора точек:

`PnLEnvelope = min(PnL) / max(PnL)`

`EffEnvelope = min(Efficiency) / max(Efficiency)`

`PlateauEnvelope = min(PnLEnvelope, EffEnvelope)`

Плато разрешено расширять только пока:

`PlateauEnvelope >= 0.75`

То есть CORE-связи обеспечивают непрерывность, а 75% не дают длинной цепочке объединить два уже экономически разных режима.

---

## 9.3. Детерминированная сборка

1. Берутся экономически допустимые точки с достаточной геометрией данных.
2. Между геометрическими соседями строятся CORE-рёбра (`>=0.90`).
3. Рёбра сортируются по `CoreLink` от большего к меньшему.
4. Компоненты объединяются только если после объединения общий `PlateauEnvelope >=0.75`.
5. После CORE-сборки к компоненте могут быть присоединены пограничные точки с локальной поддержкой `>=0.75`, если:
   - они напрямую соседствуют с CORE-частью;
   - после добавления весь envelope остается `>=0.75`.
6. Пограничная SUPPORTED-точка не может служить мостом между двумя независимыми CORE-компонентами.
7. Если одна пограничная точка подходит нескольким компонентам, она присоединяется туда, где максимальна локальная retention-связь с CORE; далее tie-break: выше max PnL компоненты, затем стабильный ID.
8. READY-плато должно иметь как минимум две CORE-связанные точки.
9. Одиночная точка без такого подтверждения не является плато.

---

# 10. Сильные изолированные пики

Изолированная точка не используется в обычном pipeline.

На отдельный аудитный лист попадает только сильная аномалия, которая:

- прошла hard gates;
- прошла standalone sample filter;
- не вошла в READY-плато;
- и одновременно выполняет хотя бы одно:
  - `PnL >= 90%` от лучшего PnL данного Pair×TF;
  - `PnL/DD >= 90%` от лучшего PnL/DD данного Pair×TF.

Статус:

`ISOLATED_PEAK`

Она не попадает в Plateau Library и не используется автоматически в MRS3.

---

# 11. Plateau Library

Plateau Library — центральный результат MRS2-селектора.

Основная сущность:

> **устойчивая зона входа и список Close MA, на которых эта зона сохраняет силу.**

Для каждого плато сохраняются:

- `plateau_id`;
- pair / side / TF;
- все реальные точки плато;
- shift-range;
- OpenMA-range;
- CloseMA-range;
- `BestPnLPoint`;
- `BestEfficiencyPoint`;
- количество CORE и SUPPORTED точек;
- `standalone_eligible` points;
- `depth_eligible` points;
- статус `READY` или `REFINE_REQUIRED`;
- Close-MA profile.

Никакого искусственного лимита числа плато на TF нет.

Никакого Pareto-отсечения плато до построения MRS3 нет.

---

# 12. Close-MA profile

Плато нельзя схлопывать до одной Close MA.

## 12.1. PRIMARY_CLOSE

Внутри плато выбирается основной PnL-представитель:

1. максимальный PnL;
2. если другая точка находится в пределах 5% одновременно и по PnL, и по PnL/DD — предпочитается больший shift;
3. далее PnL, PnL/DD, Trades, меньший DD.

Close MA этой точки становится `PRIMARY_CLOSE`.

---

## 12.2. Проверка соседних Close MA

Для соседнего периода Close MA оценивается тот же entry-regime:

- сохраняется shift PRIMARY-представителя;
- Open MA разрешено локально изменить на `±1`;
- выбирается лучший реально протестированный вариант этого среза.

Для альтернативной Close MA:

`PnL_ret = PnL_alt / PnL_primary`

`Eff_ret = Eff_alt / Eff_primary`

`CloseSupportRetention = min(PnL_ret, Eff_ret)`

Классы:

- `CORE_CLOSE` → `>= 0.90`;
- `SUPPORTED_CLOSE` → `>= 0.75`;
- `<0.75` → не считается поддерживаемой Close MA.

Close MA support должен быть непрерывным по периоду MA. От PRIMARY идем по соседним периодам `±1`; в каждом направлении рабочая цепочка заканчивается на первом неподдерживаемом Close MA.

Пример:

- Close 4 = PRIMARY;
- Close 5 = 0.92 → CORE;
- Close 6 = 0.79 → SUPPORTED;
- Close 7 = 0.68 → stop.

Рабочая Close-family этого плато: `(4, 5, 6)`.

---

# 13. Практически равноценные точки внутри плато

Две точки внутри одного плато считаются практически равноценными, если относительное отличие:

- по PnL не больше 5%;
- и по PnL/DD не больше 5%.

Среди таких вариантов предпочтение получает **больший entry shift**.

Это tie-break, а не глобальная награда за большой shift.

На текущих LONG+SHORT данных 5% показал хороший компромисс: результат почти не ухудшается, а количество входов обычно заметно уменьшается.

---

# 14. Выбор базовой 1ORD

До построения MRS3 выбирается **одна базовая standalone 1ORD для пары**.

Берутся только READY + standalone-eligible точки.

Для каждой рассчитывается:

`PnL_DD5 = PnL * 5 / DD`

Для 1ORD линейная DD5-нормализация допускается сразу как безопасный сравнительный расчет.

Выбирается максимальный `PnL_DD5`.

Если несколько точек принадлежат одному плато и практически равноценны по правилу 5%, используется больший shift.

Эта стратегия становится базовым 1ORD benchmark.

Позже, если финальный MRS3-кандидат находится на другом TF, на этом TF можно дополнительно выбрать одну лучшую 1ORD по той же логике для прямого сравнения. Если она совпадает с уже выбранной базовой — дубликат не создается.

---

# 15. Формирование MRS3 CloseMA-family

Работа выполняется отдельно для:

`Pair + Side + TF`

Для каждой потенциальной `CommonCloseMA`:

1. берутся все READY-плато, где эта Close MA имеет:
   - PRIMARY,
   - CORE,
   - или SUPPORTED status;
2. то есть `CloseSupportRetention >=0.75`;
3. если совместимых плато меньше двух, многоордерная стратегия на этой Close MA невозможна.

Каждый ордер MRS3 обязан происходить из **отдельного plateau_id**.

Две точки одного плато нельзя превратить в два ордера.

---

# 16. Конкретная entry-point плато на CommonCloseMA

Для каждого `Plateau + CommonCloseMA`:

1. берутся реальные точки плато с `close_ma == CommonCloseMA`;
2. выбирается максимальный PnL;
3. строится группа practically-equivalent points по правилу 5% PnL + 5% PnL/DD;
4. default-point = точка с максимальным shift внутри этой equivalent-группы;
5. вся equivalent-группа сохраняется, потому что она может понадобиться для соблюдения gap между ордерами.

Нельзя выходить за 5%-equivalent group только ради построения красивой лестницы.

---

# 17. Генерация MRS3 2/3/4ORD

Для каждой `Pair + Side + TF + CommonCloseMA` перебираются все комбинации разных plateau_id размером:

- 2;
- 3;
- 4.

Если плато больше четырех, заранее ничего не удаляется.

2ORD, 3ORD и 4ORD оптимизируются независимо.

Нет обязательного первого anchor.

Нет требования включать самый маленький существующий shift.

---

## 17.1. Eligibility ордеров

После выбора конкретных представителей ордера сортируются по shift.

Самый мелкий выбранный ордер должен быть:

`standalone_eligible = TRUE`

Ордера 2–4 могут быть:

`depth_eligible = TRUE`

даже если standalone sample floor ими не выполнен.

---

## 17.2. Минимальный gap

Gap проверяется между соседними ордерами после сортировки.

Если меньший shift пары:

- `<1.5%` → `gap >=0.6 п.п.`;
- `1.5–4.0%` → `gap >=0.8 п.п.`;
- `>4.0%` → правило пока не откалибровано.

Для зоны >4% структура получает:

`DEEP_GAP_RESEARCH`

и не считается обычной READY-структурой до калибровки.

План исследования: на части пар расширить MRS2 shifts минимум до 7% и на реальных Plateau + MRS3 tick-тестах определить минимальный deep-gap.

---

## 17.3. Если default representatives нарушают gap

Перебирается декартово произведение `equivalent_entry_points` выбранных плато.

Структура валидна, если существует хотя бы одна комбинация представителей, которая:

- имеет возрастающие shifts;
- удовлетворяет gap;
- имеет standalone-eligible самый мелкий ордер;
- остальные ордера depth-eligible.

Если валидных комбинаций несколько, используется порядок:

1. максимальная сумма shifts;
2. максимальная сумма исходных MRS2 PnL;
3. максимальный средний PnL/DD;
4. максимальная сумма Trades;
5. стабильный лексикографический ID.

Это правило выбирает представителей **одних и тех же плато**. Оно не предсказывает будущий MRS3 PnL.

---

# 18. Что НЕ используется для отбора MRS3 до tick-теста

Нельзя:

- суммировать MRS2 PnL и считать это ожидаемым MRS3 PnL;
- использовать искусственный ComboScore как hard filter;
- выкидывать более мелкие плато только потому, что есть более глубокие;
- требовать вложенности 2ORD → 3ORD → 4ORD.

Все структурно валидные конструкции сохраняются.

Для очередности теста их можно сортировать прозрачно:

1. выше `min_close_support`;
2. выше `source_pnl_sum`;
3. выше `source_eff_mean`;
4. меньше число low-sample depth entries;
5. при близких значениях — более глубокая комбинация.

Это только очередь, не отбор.

---

# 19. Распределение lot_x перед первым MRS3-тестом

Для каждой многоордерной структуры создаются **два варианта**.

## 19.1. EQUAL

Контрольный нейтральный вариант:

- 2ORD → `0.50 / 0.50`;
- 3ORD → `1/3 / 1/3 / 1/3`;
- 4ORD → `0.25 / 0.25 / 0.25 / 0.25`.

Последняя доля технически корректируется так, чтобы сумма была ровно 1.

---

## 19.2. INCOME

Вес каждого ордера пропорционален PnL **конкретной окончательно выбранной MRS2 entry-point на общей CommonCloseMA**:

`lot_i = PnL_i / sum(PnL_j)`

Глубокий ордер может получить больший lot_x, чем первый, если его MRS2-точка прибыльнее.

Plateau используется для валидации устойчивости точки; вес INCOME определяется фактическим PnL конкретной выбранной точки.

Перед первым MRS3-тестом:

`sum(lot_x) = 1.0`

# 20. JSON generation

Из исходного MRS3-template создается отдельный JSON на каждый вариант.

Обязательные изменения:

- `name`;
- `is_runing = false`;
- `basic.symbol`;
- `basic.time_frame`;
- `basic.use_long / use_short`.

LONG:

- `mrs3.ma_long` содержит N записей;
- `id = 1..N`;
- `len = OpenMA`;
- `multiplier = 1 - shift/100`;
- `lot_x = выбранный lot`;
- общая `ma_close_long.len = CommonCloseMA`;
- `ma_close_long.multiplier = 1.003`.

SHORT:

- `mrs3.ma_short`;
- `multiplier = 1 + shift/100`;
- общая `ma_close_short.len = CommonCloseMA`;
- `ma_close_short.multiplier = 0.997` пока как baseline.

Остальные поля шаблона не менять без отдельной причины.

SHORT close multiplier должен быть отдельно исследован после получения первой полноценной пачки SHORT MRS3.

# 21. Техническая валидация JSON

До экспорта:

- уникальное имя;
- правильная Pair / TF / Side;
- `is_runing=false`;
- ids последовательны `1..N`;
- N = 2/3/4 для MRS3;
- все ордера из разных plateau_id;
- одна CommonCloseMA;
- CloseSupport каждого plateau >=0.75;
- shifts возрастают после сортировки;
- gap соблюден;
- первый ордер standalone-eligible;
- остальные depth-eligible;
- initial lot sum = 1;
- LONG/SHORT multiplier рассчитан правильно;
- отсутствующие MRS2 cells не интерполируются;
- REFINE_REQUIRED не экспортируется как обычный READY JSON;
- DEEP_GAP_RESEARCH не экспортируется как обычный READY JSON до калибровки.

# 23. Сравнение после реального MRS3-теста

## 23.1. Нормализация риска к DD=5%

Для протестированной стратегии:

`k = 5 / DD_raw`

Все lot_x умножаются на один и тот же коэффициент:

`lot_x_DD5 = lot_x_raw * k`

На аналитическом этапе **нет ограничения `lot_x <= 1`**.

Для MRS3 линейный расчет:

`PnL_projected = PnL_raw * k`

используется только для подготовки нового теста.

После масштабирования MRS3 должна быть повторно протестирована на tick-data.

Финальными считаются фактические:

- `PnL_DD5_actual`;
- `DD_DD5_actual`;
- `lot_x_DD5[]`.

Для 1ORD допускается использовать прямую линейную DD5-нормализацию как сравнительный результат.

---

## 23.2. Капитальная нагрузка без occupancy-логов

Пока нет временного ряда фактической занятой маржи, используется консервативный proxy.

`TotalLotX = sum(lot_x_DD5)`

Если `lot_x` выражен долей депозита и выставленные ордера резервируют соответствующий капитал:

`CapitalRequirementProxy = TotalLotX + DD_DD5_fraction`

Например:

- `TotalLotX = 1.20`;
- `DD = 5% = 0.05`;

`CapitalRequirementProxy = 1.25`

Это не измеренный Peak Margin Load. Это консервативная оценка капитального пространства, требуемого стратегией.

---

## 23.3. Capital Efficiency

Внутри одной пары:

`CapitalEfficiency = PnL_DD5 / CapitalRequirementProxy`

Для сравнения историй разной длины:

`PnL30_DD5 = PnL_DD5 * 30 / D_eff`

`CapitalEfficiency30 = PnL30_DD5 / CapitalRequirementProxy`

PnL30 — нормализованная скорость результата, а не прогноз следующего месяца.

---

## 23.4. Pareto-отбор

Главные координаты:

- `PnL30_DD5` — больше лучше;
- `CapitalRequirementProxy` — меньше лучше.

A доминирует B, если:

- `PnL30_A >= PnL30_B`;
- `CapitalRequirement_A <= CapitalRequirement_B`;
- хотя бы одно неравенство строгое.

Доминируемые стратегии можно убрать из финального набора.

Если одна стратегия прибыльнее, а другая требует меньше капитала — обе сохраняются для портфельного этапа.

---

## 23.5. Близкие результаты

Если `PnL30_DD5` двух стратегий отличается не более чем на 5%, предпочтение:

1. выше `CapitalEfficiency30`;
2. затем ниже `CapitalRequirementProxy`;
3. затем больше Trades.

Никакой единый “супер-score” не нужен.

# 24. Что откладывается до портфельного этапа

Не входит в текущий селектор:

- одновременная работа разных пар;
- корреляция просадок;
- общий limiter;
- совместная margin load;
- liquidation buffer;
- приоритеты между парами;
- время занятости капитала.

Если разработчик даст entry/close timestamps или временной ряд занятости капитала, это будет добавлено позже как отдельное улучшение портфельной модели.

# 25. Вопросы для обязательной рекалибровки

По мере накопления истории и дополнительных прогонов нужно повторно проверить:

1. 5% границу practically-equivalent points.
2. CORE continuity 90%.
3. Plateau envelope 75%.
4. BaseRate_TF, особенно 30m.
5. ShiftFactor для fine-grid и больших shifts.
6. Absolute floor 10/5.
7. Economic gates: DD 11%, WR 70%, PnL/DD 3.
8. Close support: CORE 90%, SUPPORTED 75%.
9. Экономическую целесообразность shift 0.3%.
10. Fine geometry ±0.3 и пограничную зону 1.5–1.7.
11. Gap 0.6 для lower shift <1.5.
12. Gap 0.8 для 1.5–4.0.
13. Deep-gap для >4%; провести часть исследований до shift 7%.
14. EQUAL против INCOME на новой Plateau-family логике.
15. SHORT close multiplier вместо provisional 0.997.
16. Фактическую линейность DD5 scaling для MRS3.
17. Насколько `CapitalRequirementProxy` совпадает с реальной пиковой margin load.
18. Влияние времени удержания позиции/занятости капитала.
19. Надежность PnL30 на очень коротких D_eff.
