# Проверка MRS3 v0.6 на полном LONG-наборе

Дата проверки: 2026-08-08.

Проверены `MRS3_Algorithm_RU_v0.6.md`, `MRS3_Implementation_Spec_v0.6.md`,
`MRS3_HANDOFF_CLEAN_v0.6.md`, реализация селектора и полный файл
`reports_history_bybit_long_day2.csv`.

## Итог

Число 3 430 подтверждено. Оно не вызвано дубликатами или случайным
декартовым произведением:

```text
6 BASE_1ORD JSON
+ 1 712 READY MRS3 structures × 2 lot methods (EQUAL + INCOME)
= 3 430 JSON
```

Все 3 430 JSON уникальны как по имени, так и по торговым параметрам после
удаления поля `name`.

| Этап | Количество |

Исходная сетка содержит 12 пар, 7 TF, 12 shifts, 6 OpenMA и 6 CloseMA:

```text
12 × 7 × 12 × 6 × 6 = 36 288
```

Для shifts 0,3 / 0,7 / 1,1 / 1,5 отсутствует обязательная детализация 0,1.
Поэтому ровно 12 096 центров имеют `REFINE_REQUIRED` и не участвуют в READY
plateaus или JSON. Никаких значений для них программа не интерполирует.

## Происхождение MRS3

Получена 91 CommonCloseMA-family минимум с двумя совместимыми плато. Размер
family находится в диапазоне от 2 до 12 плато. Полный независимый перебор дал:

| Проверка | Количество |
|---|---:|
| Наборы плато C(K,2..4) до hard gates | 14 604 |
| Декартовы произведения 5%-эквивалентных представителей | 51 726 |
| READY 2ORD | 836 |
| READY 3ORD | 707 |
| READY 4ORD | 169 |
| Всего READY structures | 1 712 |
| Только `DEEP_GAP_RESEARCH` | 91 |

Для каждого READY structure подтверждены разные `plateau_id`, строго
возрастающие shifts, gap 0,6/0,8, standalone eligibility первого ордера,
depth eligibility остальных и одна поддерживаемая CommonCloseMA.

## Независимые проверки

- Повторно вычислены economic/history/sample/refine-флаги напрямую из
  исходного CSV: расхождений с audit нет.
- Плато пересобраны отдельным exact-rational алгоритмом: совпали все 250 ID,
  CORE и SUPPORTED membership.
- Независимо пересобраны CloseMA profiles, BASE_1ORD и все структуры:
  пропущенных, лишних или отличающихся представителей нет.
- Нет повторов `point_id`, `plateau_id`, `structure_id`, strategy name,
  filename или логического ключа структуры.
- Два чистых полных запуска создали по 3 449 файлов с одинаковыми именами и
  байтами. Digest обоих запусков:
  `72d44709afe3e8297a38e54105aa2664d31fe42e263f23beb44af228bcc4bafb`.
- После исправлений все 3 430 strategy JSON побайтно совпали с первоначальным
  результатом. Следовательно, исправления не изменили текущий отбор.

## Исправленные отклонения

В ходе ревизии исправлены дефекты, не влиявшие на число READY JSON:

1. Протестированная CloseMA вне данного plateau теперь получает
   `UNSUPPORTED_CLOSE`, а не ложный `REFINE_REQUIRED_CLOSE`.
2. Audit CSV сохраняет 17 значащих цифр float, поэтому решения на границе 0,90
   можно точно воспроизвести из выгрузки.
3. Shift-domain разрешено расширять выше 4,7%, оставляя relative sample factor
   некалиброванным, как требует v0.6.
4. Минимальный PnL и граница gap-zone вынесены в конфигурацию.
5. Порог isolated peak сравнивается с лучшей подходящей точкой всего Pair×TF,
   включая точки READY-плато.
6. JSON validator дополнительно проверяет `order_count` и фактический порядок
   ордеров по shift.
7. Manifest теперь явно показывает разложение structures и JSON и проверяет,
   что каждая READY MRS3 имеет ровно EQUAL и INCOME.

## Интерпретация результата

3 430 — большое, но ожидаемое число для действующего правила v0.6: сохранить
все структурно валидные комбинации 2/3/4ORD, ничего не отсекать Pareto/top-K до
tick-теста и создать два lot-варианта каждой MRS3. Уменьшение этого числа было
бы изменением алгоритма, а не исправлением ошибки. Для экономии времени можно
менять только очередь или размер тестовых партий, не удаляя кандидатов.

Результат относится только к текущему coarse LONG-набору. После получения
сетки 0,1 ниже 1,5% Plateau Library и количество стратегий нужно пересчитать;
оно может существенно измениться. Эти 3 430 JSON являются кандидатами на
tick-тест, а не доказанно прибыльными финальными стратегиями.
