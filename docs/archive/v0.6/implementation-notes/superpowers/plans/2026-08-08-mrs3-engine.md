# MRS3 v0.6 Deterministic Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deterministic Python CLI that converts MRS2 CSV data plus listing dates into audited MRS3 v0.6 plateaus, 1ORD selections, 2/3/4ORD EQUAL and INCOME strategy JSON files, and post-test DD5 comparisons.

**Architecture:** A source-layout Python package keeps normalized point data in pandas DataFrames and uses small pure functions for all decisions. Stable integer basis-point shift keys, sorted iteration, and content-derived hashes make repeated runs byte-for-byte reproducible. Audit, JSON export, and post-test comparison consume domain outputs without changing selection decisions.

**Tech Stack:** Python 3.11+, pandas, openpyxl, lxml, pytest, standard-library dataclasses/decimal/hashlib/json/pathlib.

## Global Constraints

- Algorithm is MRS3 v0.6; the legacy weighted PlateauScore, ComboScore, TF score, anchor, and top-K logic must not be reused.
- Plateau geometry is `Shift × OpenMA × CloseMA`; CORE link is `>=0.90`; full envelope is `>=0.75`.
- Missing mandatory cells are recorded as `SHIFT_REFINE_REQUIRED`; values are never interpolated.
- A center at `1.5%` uses boundary geometry and requires `1.2/1.3/1.4` below when those cells are inside the declared domain.
- Current coarse input may produce no READY points at or below `1.5%`; the program must still finish and emit refine requests.
- Effective history is based on listing date and must be at least 7 days for standalone eligibility.
- Economic gates are PnL `>0`, DD `>0`, WR `>=70`, DD `<=11`, and PnL/DD `>=3`.
- First order is standalone eligible; deeper orders are depth eligible; each order uses a different plateau.
- 2ORD, 3ORD, and 4ORD combinations are generated independently.
- EQUAL and INCOME initial lots each sum to exactly 1 within configured tolerance.
- Generated JSON preserves unrelated template fields and has `is_runing=false`.
- LONG close multiplier is `1.003`; SHORT close multiplier is `0.997`.
- Analytical DD5 scaling does not cap individual `lot_x` at 1; scaled MRS3 JSON requires a retest.
- All thresholds and column mappings live in JSON configuration.

## File Structure

- `pyproject.toml` — package metadata, dependencies, pytest configuration, and `mrs3` console entry point.
- `src/mrs3/config.py` — validated algorithm and input-column configuration.
- `src/mrs3/models.py` — immutable point/plateau/structure/result records and enums.
- `src/mrs3/loader.py` — CSV, listing-date, and template loading plus normalized point table.
- `src/mrs3/eligibility.py` — history, economic, sample-floor, efficiency, and DD5 fields.
- `src/mrs3/refine.py` — required shift/MA neighbors and missing-cell diagnostics.
- `src/mrs3/plateau.py` — CORE edges, envelope-constrained union-find, supported attachment, stable IDs, isolated peaks.
- `src/mrs3/selection.py` — equivalence, close profiles, BASE_1ORD, families, representative products, gaps, structures.
- `src/mrs3/lots.py` — EQUAL/INCOME lots and DD5 scaling.
- `src/mrs3/strategy_json.py` — template cloning, strategy naming, generation, and hard validation.
- `src/mrs3/audit.py` — deterministic CSV/Excel audit tables.
- `src/mrs3/posttest.py` — raw-result import, DD5 diagnostics, capital proxy, Pareto, and near-tie ordering.
- `src/mrs3/pipeline.py` — orchestration and deterministic manifest.
- `src/mrs3/cli.py` — `select` and `posttest` commands.
- `tests/` — unit and integration tests with compact hand-checked fixtures.
