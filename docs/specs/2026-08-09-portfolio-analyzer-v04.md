# MRS3 Portfolio Selector — алгоритм составления сетов
## Версия v0.4
Дата: 2026-08-09

Продолжение `MRS3_Algorithm_RU_v0.6`. Селектор v0.6 отбирает **отдельные стратегии**.
Этот документ описывает, как собрать из них **сет** для одного счёта под общим
ограничителем.

**Изменения относительно v0.3**

1. Значение ограничителя стало осью поиска: 2, 3, 4 (§6).
2. Появился общий множитель лотов. Входные `lot_x_base` из v0.6 не пересчитываются
   и не подбираются — они приходят готовыми. Но набор из нескольких таких
   стратегий даёт просадку больше 5%, потому что их просадки накладываются во
   времени. Поэтому под каждую комбинацию **вычисляется** один общий множитель,
   приводящий просадку всего набора к целевой (§5.2). При лимите 3 он больше, при
   4 меньше — это и есть механика «больше пар, меньше лот».
3. Дополнительно, как необязательная надстройка, перебираются относительные веса
   между стратегиями (§5.1). По умолчанию веса равные.
4. Маржа переписана. Считаются **две разные величины**, и в обе входят
   выставленные, но не исполненные ордера (§9).
5. Добавлены правила взаимодействия LONG и SHORT по одной паре (§7).
6. Перебор сделан двухпроходным, иначе новые оси его взрывают (§8).

---

# 1. Что на входе

Из v0.6 приходят стратегии, каждая уже **приведена к просадке 5%** своим
`lot_x` в процентах от депозита. То есть входная величина — не «сколько денег»,
а «сколько нужно денег, чтобы эта стратегия дала 5% просадки в одиночку».

```
strategy_id, pair, side, TF, orders[], lot_x_base, PnL, DD=5%, trades,
median_hold, turnover24h, D_eff
```

Внутри многоордерной стратегии соотношение лотов между ордерами **не трогаем** —
в боте для этого отдельный множитель. Вся структура масштабируется одним числом.

---

# 2. Главная мысль

На одном счёте стратегии мешают друг другу: пока слоты заняты, сигналы остальных
теряются. Поэтому результаты нельзя складывать — надо разложить все сделки по
времени и проиграть заново.

К этому добавляются две новые развилки.

**Лимит против лота.** При ограничителе 3 одновременно работают три стратегии, и
каждой можно дать лот побольше. При ограничителе 4 работают четыре, но лот у
каждой меньше — иначе суммарная экспозиция и просадка вылезут за допустимые.
Что выгоднее — заранее неизвестно, это и есть предмет перебора.

**Ордера тоже занимают маржу.** У сета из четырёх многоордерных стратегий с двумя
сторонами висит до тридцати двух заявок. Каждая резервирует маржу, даже пока не
исполнилась. Считать только по открытым позициям — значит систематически занижать
загрузку счёта.

---

# 3. Три слоя

**Слой 0 — калибровка исполнения.** По архиву стакана L2 Bybit считаем, заявку
какого размера успевают налить за время удержания. Даёт предельный размер позиции
по каждой паре. Делается один раз до всего остального.

**Слой A — аналитический.** По числу сделок и медианному удержанию считаем
занятость слотов и асимметрию таймфреймов. Режет комбинации до симуляции.
Данные для него уже есть.

**Слой B — симуляция.** Требует журналов сделок с таймстампами.

---

# 4. Слой 0 и слой A

## 4.1. Ёмкость

```
turns_per_day = trades_per_day * 2
capacity_i = turnover24h_i * target_share_i / turns_per_day
```

`target_share_i` измеряется по стакану: максимальный размер, при котором заявка
наливается полностью за `median_hold` в 90% случаев. Своя величина на пару.

Если архив L2 по паре недоступен — флаг `ESTIMATED` и консервативное значение из
измеренных пар того же класса ликвидности.

## 4.2. Занятость слотов

```
occupancy_i = trades_i * median_hold_i / period
load = sum(occupancy_i) / L
```

- `load < 0.5` — слоты простаивают, сет можно расширять.
- `0.5 .. 1.5` — рабочая зона.
- `load > 2.5` — стратегии душат друг друга, комбинация отсеивается.

## 4.3. Асимметрия таймфреймов

```
asymmetry_ij = median_hold_i / median_hold_j
```

Если `asymmetry > 20` и `occupancy` медленной стратегии выше `0.3` — комбинация
помечается `TF_ASYMMETRY` и отсеивается. Медленная займёт слот на часы, быстрая
за это время потеряет десятки сигналов подряд.

---

# 5. Лоты: что приходит готовым и что вычисляется

`lot_x_base` из v0.6 — вход, а не предмет поиска. Это лот, при котором стратегия
**в одиночку** даёт просадку 5%.

Проблема в том, что несколько таких стратегий вместе дадут не 5%: их просадки
частично накладываются во времени, и набор из трёх может выдать, скажем, 11%.
Насколько именно — заранее неизвестно и зависит от состава, лимита и синхронности
сигналов.

Поэтому вычисляется **общий множитель** `g`, приводящий просадку набора к целевой.
Он один на весь набор и не меняет соотношения между стратегиями.

Отдельно, как необязательная надстройка, можно перебирать и сами соотношения
(§5.1). По умолчанию они равные.

## 5.1. Относительные веса — надстройка, по умолчанию выключена

Раз каждая стратегия приведена к одной просадке, равные веса дают паритет по
риску, и этого обычно достаточно. Перебор нужен, только если хочется дать более
эффективной стратегии больший вес при той же общей просадке.

Сетка уровней:

```
w_i ∈ {1, 2, 3}      (уровни, а не проценты)
```

Векторы, отличающиеся общим множителем, считаются одним вариантом:
`(1,1,2)` и `(2,2,4)` — одна и та же форма.

Число форм для набора размера K:

| K | Векторов | Уникальных форм |
|---|---|---|
| 3 | 27 | 17 |
| 4 | 81 | 45 |
| 5 | 243 | 123 |
| 6 | 729 | 341 |

При выключенной надстройке все `w_i = 1`, второй проход перебора (§8.2) не
выполняется, и общая стоимость падает примерно вшестеро.

## 5.2. Общий множитель — вычисляется всегда

Итоговый лот каждой стратегии:

```
lot_i = w_i * lot_x_base_i * g
```

`g` — общий множитель, подобранный так, чтобы просадка сета попала в целевую.

**Бинарным поиском его искать нельзя.** Просадка не монотонна по `g`, и причин
две. Первая: больше `g` — каждая позиция занимает больше маржи — меньше позиций
помещается — меньше сделок — просадка может **упасть**. Вторая: если стратегия
упирается в потолок ёмкости (§5.3), дальнейший рост `g` на неё вообще не
действует.

Поэтому `g` находится сканированием сетки:

```
1. Восемь значений g, логарифмически от 0.2 до 2.0. Для каждого — полная
   симуляция, фиксируется maxDD_set(g).
2. Берётся наибольшее g, при котором maxDD_set(g) <= DD_target.
3. Три точки уточнения между ним и следующим значением сетки.
4. Если maxDD_set(g) > DD_target даже при минимальном g — флаг
   DD_TARGET_TOO_LOW: сет нельзя привести к целевой просадке.
5. Если maxDD_set(g) < DD_target даже при максимальном g — флаг
   DD_TARGET_UNREACHABLE: сет упёрся в ёмкость или в маржу, дальше не растёт.
   Это не брак, а полезная информация: такой сет безопасен, но ограничен сверху.
```

Итого 11 симуляций на одну комбинацию вместо одной. Стоимость учтена в §8.2.

`DD_target` по умолчанию 5% — та же величина, к которой приведены входные
стратегии. Это делает сравнение сетов между собой корректным: **все сравниваются
при одинаковом риске**, различаются только доходностью и требуемым капиталом.

## 5.3. Ограничение сверху

```
notional_i(t) = min( lot_i * equity(t), capacity_i )
```

Если подобранный `g` упирает какую-то стратегию в потолок ёмкости, комбинация
помечается `CAPACITY_BOUND`: дальше наращивать её нельзя, и целевая просадка
достигается только за счёт остальных.

---

# 6. Ограничитель как ось поиска

Перебираются `L ∈ {2, 3, 4}`.

Механика компромисса:

```
L меньше  -> меньше одновременных позиций -> меньше суммарная экспозиция
          -> g получается больше -> лот каждой стратегии больше
          -> но больше сигналов теряется

L больше  -> больше стратегий работает одновременно
          -> g меньше, лоты меньше
          -> но потерь сигналов меньше
```

Что перевесит — зависит от того, насколько загружены слоты и насколько
коррелированы сигналы. Считается, а не угадывается.

**Открытые вопросы по механике ограничителя**, без ответов на которые расчёт
может быть неверным:

1. Лимит считает **позиции или выставленные ордера**? У mrs2 заявки висят
   постоянно; если считаются ордера, формула `occupancy` в §4.2 неверна в разы.
2. LONG и SHORT по одной паре — это один слот или два?
3. Режим позиции: hedge или one-way?

---

# 7. LONG и SHORT по одной паре

## 7.1. Правило по умолчанию

При открытии позиции в одну сторону **заявки противоположной стороны по той же
паре снимаются**. Основания:

- в one-way режиме исполнение встречной заявки закроет или развернёт позицию, а
  это не то, что задумано стратегией;
- в hedge-режиме обе позиции экономически гасят друг друга, но занимают маржу
  вдвое;
- висящие встречные заявки резервируют маржу, которую можно отдать другим парам.

## 7.2. Обе версии считаются

Флаг `cancel_opposite ∈ {true, false}` — ещё одна ось перебора. Стоит дёшево,
разница измеряется, а не обсуждается.

## 7.3. Учёт в слотах

Если LONG и SHORT считаются разными слотами, стратегия на одну пару может занять
два. Это отражается в `occupancy` и должно быть подтверждено по пункту 2 из §6.

# 8. Перебор

## 8.1. Оси

```
состав сета     C(N, K), K от L до 3L
ограничитель    L ∈ {2, 3, 4}
форма лотов     17..341 в зависимости от K
cancel_opposite {true, false}
```

Прямое произведение взрывается. При N=15 это десятки миллионов симуляций.

## 8.2. Двухпроходная схема

**Проход 1 — равные веса.**

```
все составы × 3 значения L × cancel_opposite=true × форма (1,1,...,1)
```

При N=15: 32 631 состав × 3 значения L = 97 893 комбинации. Каждая требует
11 симуляций на поиск `g` (§5.2), итого около 1.08 млн симуляций. При 2 мс —
примерно 36 минут.

Оставляем 200 лучших по Парето.

**Проход 2 — поиск формы лотов.**

```
200 составов × все формы для их K × 3 значения L × 2 значения cancel_opposite
```

Примерно 200 × 150 × 6 = 180 000 комбинаций, по 11 симуляций каждая — около
2 млн симуляций. При 2 мс — примерно 66 минут.

**Итого около полутора-двух часов на полный перебор.** Не десять минут, как было
в первой редакции: там не учитывалось, что подбор `g` требует симуляций.

Если это окажется долго, сокращается в первую очередь сетка `g` — восемь точек
избыточны, когда первый проход нужен только для ранжирования составов. Точный
подбор можно оставить второму проходу и финалистам.

## 8.3. Проверка достаточности первого прохода

Первый проход отбирает составы при равных весах. Теоретически состав, слабый при
равных весах, может выигрывать при перекошенных.

Проверка: взять 30 случайных составов, не попавших в топ-200, прогнать по ним
полный поиск формы и сравнить с результатом двухпроходной схемы. Если ни один не
превосходит финалистов — схема принята.

# 9. Маржа

## 9.1. Две разные величины

Их постоянно путают, и они отвечают на разные вопросы.

**Маржа ликвидации** — от чего счёт умирает:

```
MM(t) = sum_positions( notional_i(t) * MMR_i )
margin_ratio(t) = MM(t) / equity(t)
ликвидация при margin_ratio = 100%
```

**Занятая маржа** — что мешает открыть следующую позицию:

```
IM_positions(t) = sum_positions( notional_i(t) * IMR_i )
IM_orders(t)    = sum_pending( order_notional_j(t) * IMR_j )
occupancy_margin(t) = ( IM_positions(t) + IM_orders(t) ) / equity(t)
```

`IMR` — initial margin rate, `MMR` — maintenance. Обе берутся из
`/v5/market/risk-limit` Bybit по фактическому размеру, тиры зависят от объёма.

## 9.2. Почему ордера обязательно считать

Сет из 4 многоордерных стратегий с двумя сторонами держит до 32 висящих заявок.
Каждая резервирует initial margin с момента выставления. Если считать только по
открытым позициям, загрузка счёта занижается кратно, и симуляция разрешит
открывать позиции, которые в реальности не откроются из-за нехватки свободной
маржи.

**В симуляции:** новая позиция открывается только если

```
occupancy_margin(t) + IM_new <= MarginLimit
```

Иначе сигнал теряется — по той же логике, что и при занятых слотах. Это второй
независимый ограничитель, помимо `L`.

## 9.3. Запас до ликвидации

```
buffer(t) = ( equity(t) - MM(t) ) / notional_total(t)
```

Доля неблагоприятного движения цены до ликвидации. В отчёт идёт минимум по
периоду.

## 9.4. Корреляция

Если стратегии сета держат однонаправленные позиции по коррелированным
инструментам, они проседают вместе, и запас на одну позицию неверен.

```
corr_matrix = корреляция дневных PnL стратегий сета
worst_day   = максимальная суммарная просадка за один день
```

Средняя парная корреляция выше 0.7 — флаг `HIGH_CORRELATION` и стресс-проверка:
одновременное движение всех пар на `worst_day * 2`, `margin_ratio` обязан остаться
ниже 100%.

# 10. Симуляция

## 10.1. Правила

1. Сигналы всех стратегий сливаются в одну временную линию по времени входа.
2. Освобождаются слоты, чьё время выхода прошло; PnL зачисляется в `wallet`.
3. Сигнал принимается, если выполнены **оба** условия: есть свободный слот и
   хватает свободной маржи (§9.2).
4. Не выполнено любое — **сигнал теряется**. Не откладывается, не ждёт.
5. Размер по §5.3, PnL и комиссии масштабируются пропорционально журналу.
6. При открытии позиции снимаются встречные заявки по паре, если
   `cancel_opposite = true`.

## 10.2. Приоритеты не перебираются

Приоритет решает только при совпадении сигналов в одну минуту — редкое событие.
Задаётся детерминированным правилом:

```
сортировка по PnL30_DD5 стратегии, убыванию
tie-break: меньший CapitalRequirementProxy, затем стабильный ID
```

Влияние остаётся диагностикой: прогнать лучший сет с обратным порядком, показать
дельту.

## 10.3. Фиксированный лот при отборе

Компаундинг включается только на финальной проверке выбранного сета и подаётся
отдельной цифрой. На этапе отбора он превращает разницу в доли процента в разы и
делает ранжирование бессмысленным.

## 10.4. Метрики конкуренции

```
acceptance_i     = accepted_i / (accepted_i + blocked_i)
blocked_by_slot  = потеряно из-за занятых слотов
blocked_by_margin = потеряно из-за нехватки маржи
blocked_by_ij    = сигналов i, потерянных пока слот держала j
```

Разделение причин блокировки важно: если сигналы теряются из-за маржи, а не из-за
слотов, то увеличение `L` не поможет — надо уменьшать лот.

**Гейт:** стратегия с `acceptance < 0.35` исключается из сета.

---

# 11. Целевая функция

Все сеты приведены к одинаковой просадке (§5.2), поэтому сравнение идёт по двум
координатам.

```
PnL30_set      = PnL_set * 30 / D_eff_common
CapitalReq_set = max_t( occupancy_margin(t) ) + maxDD_set
```

Максимизируется `PnL30_set`, минимизируется `CapitalReq_set`. Доминируемые сеты
отбрасываются, недоминируемые сохраняются все.

Ограничения:

```
maxDD_set        <= DD_target           (задан, по умолчанию 5%)
margin_load_max  <= MarginLimit         (решение, не замер)
acceptance_i     >= 0.35 для каждой стратегии
D_eff_common     >= 30 дней
```

Единый взвешенный скор не вводится: веса будут произвольными, а Парето-фронт даёт
честный выбор между «доходнее» и «дешевле по капиталу».

---

# 12. Проверка на устойчивость

При `D_eff_common >= 40 дней`:

```
1. Разрезать общее окно пополам.
2. Весь отбор — состав, L, форма лотов — выполнить ТОЛЬКО на первой половине.
3. Лучшие 10 конфигураций прогнать на второй половине без изменений.
4. В отчёт: IS, OOS, ранг в каждой половине.
```

Метрика доверия — ранговая корреляция Спирмена между половинами. На прежнем
наборе (8 пар, 33 дня, другая площадка) она составила 0.07, то есть выбор был
неотличим от случайного. Для Bybit подлежит перемеру.

Если корреляция ниже 0.3 — брать не лучшую конфигурацию, а самую устойчивую:
попадающую в верхний квартиль на обеих половинах.

При `D_eff_common < 40 дней` — флаг `NO_OOS_VALIDATION`.

# 13. Самокалибровка

Каждый прогон пишет и прогноз, и факт.

| Величина | Прогноз | Факт |
|---|---|---|
| Доля блокировок | оценка из `load` | `1 - acceptance` |
| Ёмкость | `capacity_i` | доля потока, реально занятая |
| Просадка сета | линейная от `g` | `maxDD_set` |
| Занятая маржа | оценка по номиналу | `occupancy_margin` |

Отклонения копятся в `Calibration_Log`. Величина, ни разу не сверенная с фактом,
помечается `UNVERIFIED`.

# 15. Что НЕ делается

- Не складывать PnL стратегий и не выдавать сумму за PnL сета.
- Не усреднять просадки.
- Не перебирать соотношение лотов внутри многоордерной стратегии.
- Не перебирать порядок приоритетов.
- Не отбирать по максимуму PnL.
- Не использовать компаундинг на этапе отбора.
- Не считать маржу только по открытым позициям.
- Не превышать `capacity_i` ни при каком росте депозита.
