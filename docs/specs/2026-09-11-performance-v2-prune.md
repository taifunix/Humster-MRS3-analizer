# Performance v2: безопасная очистка старых результатов

## Цель

Удалять из текущей Performance v2 базы стратегии со старым окончанием тестового
периода, сохраняя свежие стратегии и текущих пользовательских финалистов.

## Контракт

- Граница задаётся UTC-датой. При границе `2026-09-06` свежими считаются строки
  с `strategy_results.report_end_utc >= 2026-09-06T00:00:00Z`.
- Для каждой Pair+Side берётся последний импортированный пользовательский review
  последнего reviewed selection run. Стратегии с `user_status=FINALIST` в нём
  сохраняются независимо от даты.
- Остальные старые стратегии удаляются вместе с их `strategy_orders`,
  `strategy_results`, `strategy_actions`, `strategy_equity`, `window_metrics`
  и `strategy_tags`.
- Стратегия без строки `strategy_results` не считается старым тестовым результатом и
  сохраняется до отдельного решения об очистке незавершённых импортов.
- История `selection_runs`, `selection_results`, `selection_review_imports`,
  `selection_review_rows`, а также аудит импорта сохраняются.
- После очистки сохранённые `selection_results.strategy_id` и
  `selection_review_rows.strategy_id` могут ссылаться на удалённую стратегию; это
  намеренный audit trail, поэтому потребитель истории не должен требовать join со
  строкой `strategies`.
- По умолчанию команда работает только как preview и ничего не изменяет.
- Применение требует явного `--apply`, блокировки единственного writer и создаёт
  полную резервную копию базы до первого изменения.
- Перед созданием копии apply выполняет DuckDB `CHECKPOINT`; копия проверяется по
  размеру, read-only открытию и v4-схеме. При ошибке удаления транзакция
  не используется для каскада: DuckDB отклоняет удаление дочерних строк и
  ссылающегося родителя в одной транзакции. Проверенная копия восстанавливает
  файл после любой ошибки; перед этим удаляется устаревший `<db>.wal`.
- DuckDB проверяет внешние ключи между этими таблицами на границе каждого
  удаления, поэтому дочерние и родительские строки удаляются последовательно.
  При любой ошибке рабочая база восстанавливается из созданной копии.

## Non-goals

- Очистка истории автоматического ранжирования и пользовательских review.
- Сжатие файла DuckDB и обещание освобождения места на диске.
- Интерфейс Panel и автоматический запуск по расписанию.

## Acceptance evidence

- Тест доказывает сохранение свежей, старой `FINALIST` и старой `RESERVE`, а
  также полное удаление зависимостей старой непомеченной стратегии.
- Тест доказывает, что preview не меняет базу, apply создаёт backup, а backup
  содержит исходные строки.
- Параметризованный тест доказывает, что отсутствующая, пустая, повреждённая и
  чужая DuckDB-схема отклоняются в preview и apply до создания backup.
- Тест фиксирует, что writer lock удерживается во время удаления, а CLI переводит
  ошибку чтения конфигурации в argparse error без traceback.
- Focused pytest и `git diff --check` проходят.
