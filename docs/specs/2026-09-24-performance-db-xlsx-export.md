# PerformanceDB XLSX export

**Status:** Active implementation contract
**Date:** 2026-09-24

## Goal

Add a read-only XLSX download to Strategy and DD5. It exports the current ACTIVE PerformanceDB result of selected categories without a tester, job, selection recalculation, or database mutation.

## UI

The five PerformanceDB cards are exactly: `4. Pareto and filters`, `5. A/B Performance analysis`, `6. Bulk RETEST current FINALIST`, `7. CHECK & RETEST`, and `8. EXPORT FROM PERFORMANCEDB`.

Card 8 has independent `FINALIST`, `RESERVE`, and `RETEST` checkboxes, an exclusive `ALL ACTIVE` checkbox, and one download button. FINALIST and RESERVE form a union; RETEST intersects that selection, or alone selects tagged rows. No control sends an ID, path, run ID, or tester instruction.

## HTTP contract

`GET /api/v2/strategies/performance-v2/export` is the only download route. Repeated exact `status=FINALIST|RESERVE` selects their union; exact `retest=1` intersects statuses or alone selects tagged rows. Exact `all_active=true` selects all ACTIVE strategies with a matching current result and cannot mix with another filter. Invalid filters return stable JSON `400`. `HEAD` mirrors GET headers/status without a body, `OPTIONS` is `204`, other methods are `405`; all advertise `Allow: GET, HEAD, OPTIONS`.

Success is the existing Pareto-and-filters selection workbook, generated by `write_selection_workbook`: `All candidates`, `Finalists`, and its hidden review metadata sheet, with the same columns, validation and formatting. The new route only filters its rows; it defines no workbook schema or column projection. The response keeps XLSX MIME type, byte `Content-Length`, and quoted filename `performance_v2_strategies_YYYYMMDDTHHMMSSZ.xlsx`.

## Data and safety invariants

Rows use `strategy_results.result_id = strategies.current_result_id` and the matching strategy ID. `FINALIST`/`RESERVE` come only from `effective_selection_decisions`; `RETEST` comes only from `strategy_tags`. Ordering is FINALIST, RESERVE, other, then strategy name, symbol, timeframe, result ID, and strategy ID, with `NULLS LAST`. The route reads at most 100,001 rows; a 100,001st row returns `413` before workbook creation.

The route uses the established one-request `duckdb.connect(..., read_only=True)` pattern used by catalog and RETEST status. It does not call `_ensure_performance_v2_schema`, retry, poll, pool, or add an accessor. A DuckDB lock is `409 PERFORMANCE_DB_BUSY`; a missing/unavailable DB is `503 PERFORMANCE_DB_UNAVAILABLE`.

The workbook contract belongs solely to Pareto and filters. This export must call that existing writer rather than copy its headers, formatting, validation, formula handling or workbook metadata.

## Non-goals

No review round trip, DB/schema mutation, selection recalculation, cached A/B calculation, tester action, portfolio behaviour, generic export framework, background job, dependency, or client-side identity filter is added.

## Acceptance evidence

Focused tests prove category union/deduplication, active/current joins, validation/method handling, lock/unavailable mapping, equality with the Pareto workbook structure, and unchanged database bytes/schema/mtime and tester/import/job entry points.
