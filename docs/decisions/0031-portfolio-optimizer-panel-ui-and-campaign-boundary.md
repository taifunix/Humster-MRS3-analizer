# ADR-0031: Panel UI и неизменяемая граница Campaign Portfolio Optimizer

**Дата:** 2026-09-06
**Статус:** Accepted
**Связано:** [UI-спецификация](../specs/2026-09-06-portfolio-optimizer-panel-ui.md),
[основная спецификация](../specs/2026-09-05-portfolio-optimizer.md),
[ADR-0030](0030-portfolio-optimizer-m2-admission-and-sizing-contract.md),
[план](../superpowers/plans/2026-09-05-portfolio-optimizer.md).

## Контекст

Оптимизатору нужен минимальный управляемый запуск из существующей Panel,
просмотр хода расчёта и проверяемая выгрузка результата до передачи вариантов
портфельному тестеру. Настройки и PerformanceDB могут меняться во время
длительного расчёта, браузер и сервер могут перезапускаться, а XLSX будет
редактироваться человеком. Поэтому UI не может быть владельцем алгоритмов или
источником воспроизводимости.

## Решение

1. Используется существующая локальная Panel: вкладка `Portfolio` становится
   рабочим местом оптимизатора, а в существующей вкладке Settings появляется
   один сворачиваемый раздел его настроек. Второе приложение не создаётся.
2. Граница запуска — новый неизменяемый Campaign. До постановки задания сервер
   атомарно фиксирует проверенные поля запуска, точные байты/digest настроек,
   версии и порядок входных данных. Последующие изменения настроек действуют
   только на новые Campaign.
3. Состояния и журнал задания сохраняются серверным реестром Panel. После
   рестарта незавершённое задание становится `INTERRUPTED`; автоматического
   продолжения нет. Одновременно выполняется одно задание оптимизатора.
4. Отбор финалистов, порядок, расчёты и генерация вариантов принадлежат только
   пакету `src/mrs3/portfolio`. Frontend и адаптер Panel не пишут в
   PerformanceDB и не повторяют алгоритмы.
5. Файл настроек сохраняется целиком с CAS по SHA-256 точных прочитанных байтов:
   проверка, временный файл в той же папке, flush/fsync, `os.replace`, повторный
   разбор и восстановление прежних байтов при неудаче проверки. Неизвестные
   ключи отклоняются; неподдерживаемая схема доступна только для чтения.
6. Результат публикуется только после `SUCCEEDED`. XLSX содержит зафиксированные
   значения, стабильные идентификаторы и скрытые метаданные происхождения, но
   не формулы, макросы, внешние ссылки, локальные пути или секреты.
7. XLSX не загружается обратно на MVP. Будущая совместимость полей ручного
   выбора не делает книгу входом этапа 2.
8. Этап 2 требует отдельного подтверждения, готовности M5/M6 и явного разрешения
   на запуск тестера. Пока маршрут объявлен, но всегда закрыт каноническим
   `PORTFOLIO_JOB_STAGE2_NOT_AUTHORIZED`; сокращённая форма кода запрещена.
9. Значения локальных путей разрешены только в Settings GET/PUT локальной Panel.
   Во всех остальных ответах, журналах, ошибках и книгах они скрыты.
10. Необязательный `max_balance_usdt` Campaign не меняет строгую схему v1, где
    `scenarios[].max_balance` обязателен. Nullable/omittable config и возможные
    UI defaults требуют отдельной принятой схемы v2 и поддержки parser.
11. UI — отдельная сквозная дорожка. Его отсутствие не блокирует M2 и другие
    серверные этапы.

## Отклонённые варианты

- отдельное приложение для оптимизатора;
- расчёт и усечение финалистов во frontend;
- прямой доступ Panel к PerformanceDB для записи;
- прогресс только в памяти браузера;
- частичное исправление JSON вместо сохранения полного принятого документа;
- сохранение неизвестных ключей строгой схемы;
- использование порядка строк или обратной загрузки XLSX для этапа 2;
- выдача частичной книги после ошибки или отмены;
- включение тестера до готовности восстановления и отдельного разрешения.

## Последствия

- расчёт воспроизводим после изменения настроек, а пользователь видит честное
  состояние после перезагрузки;
- API, схема задания, идентификаторы и заголовки XLSX становятся версионируемыми
  контрактами;
- до будущего импорта нужны отдельные миграция и правила проверки изменённых
  пользователем полей;
- политика очистки старых заданий и книг откладывается до отдельного контракта;
- удалённый доступ, config v2 и runtime тестера остаются отдельными работами;
- основная спецификация Portfolio Optimizer и ADR-0030 сохраняют приоритет над
  UI-спецификацией и этим ADR для всех правил допуска, ликвидности, leverage,
  размера позиции и индивидуальной просадки; D7 сохраняет смысл D6 в этой части.
