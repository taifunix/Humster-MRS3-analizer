# ADR-0080: Отметки финалистов хранятся только в реестре пар

**Status:** Accepted. Это решение пользователя от 2026-10-18 из спецификации
Panel. Реализация — этап 4 Panel, подэтапы 4a и 4b.
**Date:** 2026-10-19
**Contracts:**
- [Panel для симуляционного процесса](../specs/2026-10-18-panel-simulation-workflow.md)
  (вид «Стратегии», «Stage 4 contract»);
- [реестр пар](../specs/2026-10-18-pair-registry.md) (таблица `finalists`).

## Context

До этого этапа отметки FINALIST / RESERVE / REJECTED и ранг пользователя
ставились в XLSX экрана Pareto. Затем они импортировались в PerformanceDB как
отзыв (`selection_review_imports` / `selection_review_rows`). Выгрузка XLSX
при этом сама писала в базу: создавала запуск отбора и теги REJECTED.

От этих отзывов зависели:
- ретест финалистов;
- входные данные оптимизатора.

С этапа 3 реестра конвейер копирует последнюю отметку каждой стратегии в
таблицу реестра `finalists` (источник `performance_db`).

PerformanceDB локальна для машины. Реестр синхронизируется между машинами
(этап 5 реестра). Пользователь решил так:
- отметка ставится прямо в таблице вида «Стратегии»;
- хранится она только в реестре;
- выгрузка в Excel ничего не пишет в базу;
- оптимизатор и ретест берут финалистов из реестра.

## Decision

1. **Единственное хранилище отметок — таблица реестра `finalists`.** Она
   только дополняется: действует последняя строка по стратегии, а история и
   есть журнал изменений. Стратегия определяется по имени (`strategy`). Имя
   стабильно: его порождает папка READY, а подготовка тик-теста проверяет,
   что оно не изменилось.
2. **Кто пишет:**
   - таблица вида «Стратегии» (источник `panel`);
   - загрузка отметок из Excel (`excel`);
   - исход ретеста финалистов (`retest`, подэтап 4b).
3. **Перенос старых отметок.** Отметки из PerformanceDB копируются
   однократно, пока в реестре нет ни одной отметки этой биржи. Дальше
   конвейер их не импортирует, иначе он перетирал бы отметки, поставленные в
   Panel.
4. **Выгрузка без побочных эффектов.** Excel вида «Стратегии» — это ровно
   показанные строки с отметками, рангами и стабильным именем стратегии.
   - Фильтры пересчитываются при показе и нигде не хранятся.
   - Запусков отбора и тегов REJECTED больше нет.
   - Загрузка отметок сопоставляет строки по имени стратегии и записывает
     только изменения.
5. **Потребители (подэтап 4b):** ретест финалистов и входные данные
   оптимизатора берут действующие отметки из реестра. Стратегию в
   PerformanceDB они находят по имени. Отзывы PerformanceDB остаются
   историей и больше не определяют финалистов.

## Consequences

- Отметки одинаковы на обеих машинах, когда синхронизирован реестр.
  PerformanceDB для них не нужна.
- Пока не сделан подэтап 4b, отметка из Panel видна в реестре и в конвейере,
  но ретест и оптимизатор её ещё не читают. 4a и 4b сдаются в одной работе.
- Экран Pareto, его запуски отбора и импорт отзывов XLSX выводятся из
  использования (подэтап 4c). Код, который читает старые отзывы, остаётся
  для истории и миграции.
- Отметка привязана к имени стратегии, а не к `strategy_id` базы. Поэтому
  отметка переживает новую базу, если стратегию снова протестировать под тем
  же именем.
