# ADR-0079: LOT_MODEL_V2 — ликвидность только по будням, окно в N будней, значения из реестра пар

**Status:** Accepted (решение пользователя 2026-10-18; реализация — этап 2 реестра пар)
**Date:** 2026-10-18
**Contracts:** [реестр пар](../specs/2026-10-18-pair-registry.md) (таблица `liquidity`, этап 2), [модель лота по ликвидности](../specs/2026-09-27-liquidity-lot-model.md), [экспорт базового лота](../specs/2026-10-07-bybit-base-lot-export.md)

## Context

`LOT_MODEL_V1` (`minute_capacity._lot_model_capacity`, экспорт базового лота)
считает `V25` (Q25 положительного минутного оборота) и `A15` (доля активных
15-минутных интервалов) по семи **календарным** дням подряд, включая субботу и
воскресенье. У бессрочных контрактов на акции выходные торги тонкие: они
занижают и `V25`, и `A15`, поэтому базовый лот зависит от того, сколько
выходных попало в окно. Кроме того, оптимизатор и экспорт сами читают минутные
файлы и знают длину окна.

## Decision

1. **Только будни.** Все показатели ликвидности считаются по дням UTC с
   понедельника по пятницу. Субботы и воскресенья хранятся в реестре как дневные
   строки с пометкой, но в окно не входят никогда.
2. **Окно — последние N будней**, по умолчанию 7, настройка реестра
   `pair_registry.liquidity.window_weekdays`. Изменение действует со следующего
   обновления. На каждой строке окна записываются использованные дни, но
   потребители длину окна не знают.
3. **Формулы те же, что в V1,** только по будням:
   - `V25` — Q25 (type 7) положительного минутного оборота дней окна;
   - `A15` — активные 15-минутные интервалы / (N × 96);
   - `L = V25 × A15`;
   - базовый лот = `floor_to_step(K × L, step)`, `K = 9`, шаг 10 USDT (как в V1).
4. **Сырые входы хранятся в реестре** (таблица `liquidity`): дни окна, число
   положительных минут, активные и все интервалы, `V25`, `A15`, `L`, `K`, шаг,
   версия модели `LOT_MODEL_V2` и базовый лот. Геометрию стратегии
   (`B = min_i(M(s_i) / W_i)`, `N_max = K × L × B`) оптимизатор применяет сам,
   по сохранённым значениям, без чтения минутных файлов.
5. **Потребители** — оптимизатор и экспорт базового лота — переходят на чтение
   через `mrs3.pair_registry`. До перехода V1 работает как прежде. Версия модели
   записывается в каждом результате, поэтому смешать V1 и V2 незаметно нельзя.

## Consequences

- Базовый лот V2 на тот же день отличается от V1: обычно он выше у пар с тонкими
  выходными. Старые результаты оптимизатора помечены `LOT_MODEL_V1` и не
  пересчитываются задним числом.
- День без минутного файла внутри окна делает окно недоступным
  (`LIQUIDITY_MODEL_WINDOW_UNAVAILABLE`, как в V1); отсутствующие минуты внутри
  файла означают отсутствие сделок.
- Окно из N будней охватывает больше календарных дней, чем N, поэтому старт
  новой пары откладывается до появления N будних дней с данными.
