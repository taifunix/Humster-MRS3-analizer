# ADR-0043: PerformanceDB read-only XLSX export

**Status:** Accepted
**Date:** 2026-09-24

## Decision

Expose one GET-only, in-memory XLSX export for current ACTIVE PerformanceDB results. Categories are resolved on the server from effective selection decisions and RETEST tags; the browser submits only category filters.

The export opens one direct DuckDB `read_only=True` connection, following the existing catalog and RETEST-status read pattern. It deliberately does not call the catalog's schema-initialization helper: export must never create or modify database objects. Lock contention is typed 409; unavailable DB is typed 503. There is no retry loop or connection pool.

XLSX bytes are generated by the existing Pareto-and-filters `write_selection_workbook` path, unchanged in schema, sheets, column order, formatting, validation and metadata. This route owns only category filtering. A response is capped at 100,000 rows; 413 is the documented response-size guard before serialization.

## Consequences

Operators can download FINALIST, RESERVE, their union, RETEST alone, a FINALIST/RESERVE selection intersected with RETEST, or all ACTIVE strategies with no tester/import side effect. A temporary writer lock can make export unavailable; the operator can retry after the writer completes.
